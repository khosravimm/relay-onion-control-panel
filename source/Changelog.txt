2.11.0.0 (Descriptor Retrieval Mode):
- Added a visible Descriptor Mode setting: Auto, Microdescriptors, or Full descriptors.
- Auto preserves Tor's default behavior by removing any explicit UseMicrodescriptors override.
- Microdescriptors writes UseMicrodescriptors 1; Full descriptors writes UseMicrodescriptors 0.
- Descriptor Mode is persisted as Main/DescriptorMode and routed through the canonical torrc configuration model.
- Full descriptors is an explicit operator-selectable diagnostic/fallback mode; no automatic recovery claim or hidden switching is made.
- Direct-path qualification in the current network remains open; obfs4 is the verified working fallback.
2.10.0.0 (Local Read-Only MCP Runtime):
- Added MCPConnect-based local HTTP MCP runtime to the shared Machine Interface service.
- Added MCP 2026-07-28 server/discover and tools protocol support.
- Added three read-only tools only: tcp_version, tcp_status, tcp_health.

- Missing Mcp-Method, missing Mcp-Name and missing required _meta are rejected by protocol validation.
- Disabled weak-linked RTTI for the executable because MCP/JRPC runtime parameter deserialization requires retained extended RTTI.
- Remote MCP and state-changing MCP tools remain disabled and outside this release gate.

- Added HTTP 404 and 405 handling, no-store responses and explicit connection-close semantics.
- Added transport-level API key authentication via Authorization: Bearer and X-TCP-API-Key.
- Loopback remains keyless by default; optional loopback key enforcement is supported.
- Runtime binding is intentionally limited to loopback in this release stage; remote REST binding remains gated for a dedicated validation stage.
- Added listener lifecycle integration with TCP startup, settings Apply and shutdown.
- Hardened settings mutation: listener stops before settings changes and generated API keys remain pending until Apply.
- Added thread-safe shared status reads/writes for machine clients.
